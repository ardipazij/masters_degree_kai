# Сеть АЗС — аналитика и прогнозирование (Temporal Fusion Transformer)

Веб-приложение и пайплайн машинного обучения для почасового прогноза продаж топлива по маркам, суммарного топлива и выручки магазина на сети АЗС. Модель — **Temporal Fusion Transformer (TFT)** из библиотеки [pytorch-forecasting](https://pytorch-forecasting.readthedocs.io/), интерфейс — **Streamlit**.

## Назначение системы

Система решает три практические задачи для сети АЗС:

| Задача | Как реализовано |
|--------|------------------|
| **Исследование данных** | Интерактивная аналитика по сети и по отдельной АЗС (Plotly, фильтры по периоду) |
| **Прогноз спроса** | TFT с горизонтом 24 часа, encoder 168 часов |
| **Поддержка решений** | Сценарии «что если» (акции), эвристические рекомендации, матрица риска прогноз vs базис |

Модель учитывает трафик, цены (свои и конкурентов), погоду, календарь, акции, рекламу и статические характеристики АЗС.

## Возможности

- Обучение TFT на своём CSV или встроенных наборах (`5stations_data.csv`, `detailed_data.csv`).
- **9 целей прогноза**: сумма топлива, 7 марок, выручка магазина.
- Реестр версий моделей: каждый запуск обучения сохраняется отдельно, можно переключать активную модель.
- Прогноз в дашборде: один показатель, все марки топлива на одном экране, таблица по шагам.
- Метрики **MAE** и **R²** на валидации.
- Сценарий с изменением `promotion_fuel_active` на горизонте decoder.
- Важность признаков TFT (или запасной вариант — корреляции).
- Экспорт отчёта в Markdown.
- **Фоновые задачи**: обучение, predict, метрики и отчёты не блокируют интерфейс — можно переключать разделы во время расчёта.
- Кэширование CSV и списка целей модели — быстрее открытие разделов.
- Индикатор фоновой задачи вверху страницы + кнопка **«Обновить статус»**.

## Установка

### 1. Клонирование и переход в каталог

```bash
cd /path/to/6-th_lab
```

В корне должны лежать CSV (`detailed_data.csv` и/или `5stations_data.csv`).

### 2. Виртуальное окружение

```bash
python3.13 -m venv .venv
source .venv/bin/activate   # Linux / WSL
# .venv\Scripts\activate    # Windows (cmd)
```

### 3. Зависимости (рекомендуется `uv`)

```bash
pip install uv
uv pip install -e ".[dev]" --python .venv/bin/python
# или без editable:
uv pip install torch lightning pytorch-forecasting pandas numpy scikit-learn streamlit plotly matplotlib --python .venv/bin/python
```

Установка из `pyproject.toml`:

```bash
uv pip install -e . --python .venv/bin/python
```

### 4. PyTorch с CUDA (при наличии GPU)

Если GPU не подхватывается, установите сборку PyTorch с CUDA с [pytorch.org](https://pytorch.org/get-started/locally/) под вашу версию драйвера.

### 5. Проверка

```bash
export PYTHONPATH=src   # обязательно для импорта azs_tft
python -c "from azs_tft.train import build_datasets; from azs_tft.preprocess import default_csv, load_panel, time_split; print('OK')"
```

|------|------------|
| `detailed_data.csv` | Основной ряд: все АЗС, почасовые записи |

### Обязательные колонки (минимум для обучения)

Проверяются в разделе **«Обучение»** и в `analytics.validate_csv_schema`:

Формат должен совпадать с `detailed_data.csv`. Загрузка:

Файл сохраняется во временный каталог (`/tmp/azs_tft_streamlit/...`).

### Разбиение train / validation

По умолчанию последние **336 часов** (14 суток) — валидация, остальное — обучение (`preprocess.time_split`).

## Обучение модели (CLI)

### Команда

```bash
PYTHONPATH=src python -m azs_tft.train [опции]
```

или после `pip install -e .`:

```bash
azs-train-tft --csv 5stations_data.csv --epochs 25
```

### Параметры

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `--csv PATH` | — | Путь к CSV (приоритет над `--data`) |
| `--data` | `5stations` | `5stations` или `full` → встроенный файл |
| `--epochs` | `25` | Число эпох |
| `--batch-size` | `64` | Размер батча |
| `--num-workers` | до 4 | Потоки DataLoader (`0` — только главный процесс) |
| `--limit-train-batches` | `0` | Лимит батчей за эпоху (`0` = без лимита, для отладки) |

### Примеры

```bash
# Полный датасет, 30 эпох
PYTHONPATH=src python -m azs_tft.train --csv detailed_data.csv --epochs 30 --batch-size 64

# Быстрая проверка пайплайна (1 эпоха, мало батчей)
PYTHONPATH=src python -m azs_tft.train --csv 5stations_data.csv --epochs 1 --limit-train-batches 5
```

### Гиперпараметры TFT (в коде `train.py`)

| Параметр | Значение |
|----------|----------|
| `max_encoder_length` | 168 ч (7 суток истории) |
| `max_prediction_length` | 24 ч (горизонт прогноза) |
| `hidden_size` | 32 |
| `learning_rate` | 0.03 |
| `loss` | `MultiLoss([MAE() × 9])` — по одной MAE на каждую цель |
| Early stopping | `val_loss`, patience 5 |

После обучения лучший чекпоинт копируется в `artifacts/tft_azs.ckpt`, параметры датасета — в `artifacts/tft_dataset_params.pt`, запись добавляется в реестр и становится **активной**.

### Обучение из дашборда

Раздел **«Обучение»** → загрузить CSV или выбрать встроенный набор → **«Запуск обучения»**.

Обучение запускается **в фоне** (отдельный процесс `python -m azs_tft.train`):

- кнопка сразу освобождается — можно уйти в **Сеть** или **Аналитика**;
- вверху страницы — панель «Выполняется в фоне: Обучение TFT» и хвост лога;
- по завершении откройте снова **Обучение** или нажмите **«Обновить статус»** — появится журнал и запись в реестре.

Перед запуском показывается проверка схемы CSV.

- Таблица переменных из `data_dictionary.json` (имя, тип, описание).

| Подвкладка | Содержимое |

| **Трафик и цены** | Продажи vs трафик; area по типам ТС; scatter цена–продажи (линейный тренд); цены сети и конкурента |
| **Календарь** | Будни / выходные / праздники; погода; столбик «акция vs нет» |
| **Сравнение с сетью** | Рейтинг всех АЗС по выбранному показателю |

| Шаг | Действие |
|-----|----------|

- Выбор run → JSON метаданных, график `train_loss` / `val_loss` (если есть `metrics.csv`).

- **«Расчёт MAE и R²»** — **фоновая задача**; таблица по целям появится на этой странице после готовности.

#### Прогноз

Требуется `artifacts/tft_azs.ckpt` и `tft_dataset_params.pt`.

| Элемент | Описание |
|---------|----------|

| Слайдер | Глубина истории на графике (24–168 ч) |
| **Один показатель** | Plotly: история + прогноз + полоса P10–P90 (оценка по историческому разбросу, не квантили TFT) |
| **Все марки топлива** | До 7 подграфиков, **один** `model.predict` |
| Expander | Диагностика matplotlib (`plot_prediction` pytorch-forecasting) |

Все три кнопки прогноза — **фоновые**; график появится на **Прогноз** после завершения.

#### Сценарии

Toggle **акция на топливо** на горизонте decoder → **«Расчёт сценариев»** (фон, ~2× один predict). Таблица: базовый vs сценарий с акцией.

#### Интерпретация

**«Важность признаков»** (фон) — bar chart attention encoder + таблица (или fallback по корреляциям).

#### Рекомендации

- Текстовые сигналы по последним **14 суткам** (эвристики, без TFT).
- График влияния акции на топливо.
- **«Матрица риска»** (фон, **самая долгая** операция: отдельный predict на каждую АЗС).

#### Экспорт

**«Собрать отчёт»** (фон) → кнопка скачивания `azs_tft_report.md` + предпросмотр.

## Фоновые задачи и отзывчивость UI

### Как это работает

Streamlit по умолчанию **однопоточный**: пока выполняется `model.predict` или чтение лога обучения в том же скрипте, браузер «замирает». В актуальной версии тяжёлые операции вынесены в модуль `dashboard_jobs.py`:

1. По нажатию кнопки создаётся запись `st.session_state["bg_job"]`.
2. Расчёт идёт в **фоновом потоке** (daemon thread).
3. Скрипт сразу завершает rerun — интерфейс снова отзывчив.
4. Вверху главной области — синяя панель с названием задачи, progress и (для обучения) хвостом лога.
5. Нажмите **«Обновить статус»** или переключите **Раздел** — увидите актуальный прогресс.

### Что выполняется в фоне

| Кнопка / раздел | Задача |
|-----------------|--------|
| Обучение → Запуск | Subprocess `azs_tft.train` |
| Модель → MAE и R² | `evaluate_validation_metrics` |
| Прогноз → Один показатель / Все марки / matplotlib | `plot_forecast_*`, `plot_prediction_example` |
| Таблица → Сформировать | `forecast_steps_table` |
| Сценарии → Расчёт | `scenario_promo_compare` (2× predict) |
| Интерпретация → Важность | `variable_importance_tft` |
| Рекомендации → Матрица риска | `station_risk_table` |
| Экспорт → Собрать отчёт | `build_report_markdown` |

### Одна задача за раз

Одновременно может выполняться **только одна** фоновая задача (ограничение по RAM/GPU и потокобезопасности PyTorch). При попытке запустить вторую появится предупреждение: *«Уже выполняется: …»*. Дождитесь завершения или закройте уведомление после ошибки.

**Это не баг:** два параллельных predict на CPU обычно замедляют систему сильнее, чем очередь из одной задачи.

### Где смотреть результат

| Статус панели | Действие пользователя |
|---------------|------------------------|
| `running` | Можно свободно ходить по разделам; смотреть лог / progress вверху |
| `done` | Откройте раздел, где нажимали кнопку (например **Прогноз**) — график/таблица уже там; или **«Сбросить результат»** |
| `error` | Текст ошибки на панели и на странице задачи; **«Закрыть»** / **«Сбросить»** |

После **«Применить»** другую модель или успешного обучения кэш Streamlit сбрасывается (`st.cache_data.clear()`).

## Метрики качества (MAE, R²)

Считаются на **валидационном** отрезке в **нормализованном** масштабе (`GroupNormalizer` по `station_id`), не в литрах/рублях напрямую.

| Метрика | Интерпретация |
|---------|----------------|
| **MAE** | Средняя абсолютная ошибка; меньше — лучше |
| **R²** | Доля объяснённой дисперсии; ближе к 1 — лучше; отрицательное — хуже среднего |

Для сравнения моделей и целей между собой нормализованный MAE/R² подходят. Для отчёта в физических единицах нужна дополнительная денормализация через `target_scale` (в текущем UI не выведена).

Ограничение: по умолчанию до **50 батчей** валидации (`limit_predict_batches`) — для ускорения кнопки в дашборде.

## Цели прогноза и марки топлива

Порядок целей при обучении (`targets_config.default_model_targets`):

1. `total_fuel_sales` — сумма топлива  
2. `sales_AI92`, `sales_AI95`, `sales_AI98`  
3. `sales_DT_EURO`, `sales_DT_TANEKO`, `sales_DT_SUMMER`, `sales_DT_WINTER`  
4. `shop_total_revenue` — магазин  

Марки больше **не** дублируются в `time_varying_unknown_reals` — каждая является отдельной **target**.

**Прогноз по марке** возможен только если модель обучена с этими targets (9 целей). Иначе в UI доступны только «Сумма топливо» и «Магазин».

## Прогресс и длительность операций

В фоновых задачах прогресс обновляется через callback `report(step, total, message)`:

- значение **progress** на панели вверху (0–100%);
- текст этапа в подписи панели.

Типичные этапы **predict** (внутри фонового потока):

1. Подготовка валидационного `TimeSeriesDataSet`  
2. Загрузка чекпоинта (при первом predict в сессии — с диска; далее из кэша в памяти)  
3. **`model.predict` по всему DataLoader** — основное время  
4. Разбор `Prediction.output` / MultiLoss  
5. Построение Plotly / таблицы  

На этапе 3 индикатор может долго стоять на одном значении — Lightning не отдаёт промежуточные батчи в UI.

## Производительность: что быстро, что долго

Ориентиры на **CPU**, `5stations_data.csv` (меньше) vs `detailed_data.csv` (~219k строк):

| Действие | Ожидаемое время | Примечание |
|----------|-----------------|------------|
| Переключение раздела (Сеть, Справочник, Аналитика) | ~1–5 с | После кэша CSV; без predict |
| Первое открытие с `detailed_data` | ~5–15 с | Однократное чтение CSV в кэш |
| Открытие **Прогноз** (без кнопок) | ~1–3 с | Список целей из meta/params, не из TFT |
| Один predict (кнопка на Прогноз) | ~30 с – 3+ мин | GPU сильно быстрее |
| Все марки топлива | как один predict | Не 7× |
| MAE/R² (до 50 батчей val) | ~1–5 мин | Фон |
| Обучение 15 эпох, 5 АЗС | минуты – часы | Фон + subprocess |
| Матрица риска | **N × predict** (N = число АЗС) | Самая долгая кнопка |

### Рекомендации пользователю

1. Для освоения интерфейса держите **`5stations_data.csv`** в источнике данных.  
2. **`detailed_data`** — для финального обучения и отчётов.  
3. Не нажимайте **Матрица риска** и **Обучение** одновременно — вторая кнопка будет отклонена.  
4. Во время фоновой задачи переключайте разделы; для обновления прогресса — **«Обновить статус»**.  
5. При наличии NVIDIA установите PyTorch с CUDA (см. [Установка](#установка)).

## Устранение неполадок

### `ModuleNotFoundError: No module named 'azs_tft'`

```bash
export PYTHONPATH=src
# или установите пакет: uv pip install -e .
```

### `FileNotFoundError: Нет чекпоинта`

Сначала обучите модель (CLI или вкладка «Обучение»).

### Ошибка при predict / несовпадение targets

Чекпоинт обучен на другом числе целей. Переобучите или выберите в реестре совместимый run.

### `StreamlitDuplicateElementId`

У кнопок должен быть уникальный `key=` — в актуальной версии исправлено. Обновите код и перезапустите Streamlit.

### Интерфейс «зависает» / вкладки не переключаются

Убедитесь, что запущена **актуальная** версия кода (навигация **в сайдбаре**, панель фоновой задачи вверху). Старая сборка с `st.tabs` пересчитывала все 11 страниц за раз.

Если зависание **после** обновления:

- идёт фоновая задача — переключение разделов должно работать; обновите статус;
- выбран `detailed_data` на слабом CPU — ожидайте секунды на каждый rerun;
- нажата **Матрица риска** — ждите завершения (десятки минут на полном наборе).

### Predict 5–10+ минут

- Используйте GPU и `5stations_data.csv` для отладки.  
- «Все марки топлива» — **один** predict.  
- «Матрица риска» — predict **по каждой АЗС**; запускайте осознанно.

### Вторая кнопка не запускается

Сообщение *«Уже выполняется: …»* — нормально: активна одна фоновая задача. Дождитесь `done` или закройте панель после ошибки.

### Предупреждение NumPy `not writable`

Безвредно для PyTorch; частично подавляется в коде. На результат обычно не влияет.

### CUDA out of memory

Уменьшите `--batch-size` (например 32 или 16).

### Слабый R² / высокий MAE

Увеличьте `--epochs`, проверьте качество данных, попробуйте полный датасет; для production — подбор `hidden_size`, learning rate, quantile loss.

## Частые вопросы

**Нужна ли модели «целевая метрика»?**  
Да, в двух смыслах: (1) **целевые переменные** (`target`) — что прогнозируем; (2) **функция потерь** (MAE) — как оцениваем ошибку при обучении. MAE/R² в дашборде — отчётные метрики после обучения.

**Почему P10–P90 на графике не от модели?**  
Сейчас это оценка по историческому разбросу остатков. Настоящие квантили TFT требуют обучения с `QuantileLoss` / несколькими квантилями.

**Можно ли прогнозировать 48+ часов?**  
Нужно изменить `max_prediction_length` в `train.py` и переобучить.

**Где хранить API-ключи?**  
В `.env` (файл в `.gitignore`). Не коммитьте пароли и ключи в CSV/код.

**Почему нельзя запустить прогноз и обучение одновременно?**  
Одна очередь фоновых задач: экономия памяти и стабильность PyTorch. Интерфейс при этом не блокируется — можно смотреть **Сеть** / **Аналитика**, пока в фоне идёт обучение.

**Куда делись вкладки вверху?**  
Заменены на **Раздел** в боковой панели — так быстрее и понятнее статус фоновых задач.
